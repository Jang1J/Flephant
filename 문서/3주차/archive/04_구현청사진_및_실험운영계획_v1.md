# 구현 청사진 및 실험 운영계획 v1

> 목적: “그래서 실제로 어떻게 만들 것인가?”에 답하는 문서.  
> 이 문서는 설계서를 구현 가능한 형태로 내려서, **클래스 / 파일 구조 / 카드 스키마 / 실행 순서 / 실험 / WBS**까지 연결한다.

---

## 0. 이 문서의 사용법

- **AI 팀**: Strategy/Risk/Backtest 내부 구조와 실험 설계를 본다.
- **BE 팀**: Orchestrator, Artifact Registry, API boundary를 본다.
- **FE 팀**: 어떤 카드와 어떤 trace를 시각화해야 하는지 본다.
- **PM**: 각 모듈의 owner와 일정 리스크를 본다.

---

## 1. 구현 철학

1. **먼저 contract를 고정하고, 그다음 모델을 넣는다.**
2. **MVP는 돌아가는 end-to-end loop가 우선이다.**
3. **모든 모듈은 artifact를 남겨야 한다.**
4. **실험 가능성(ablation)을 유지하면서 구현한다.**
5. **후속연구용 확장은 runtime core와 분리한다.**

## 6. 일일 실행 의사코드

```python
def daily_run(trading_date):
    packet = data_agent.run(trading_date)
    strategy = strategy_agent.run(packet)
    risk = risk_agent.run(strategy)
    report, failure = backtest_agent.run(risk)

    if failure is not None and retry_policy.allow_once(trading_date):
        strategy_retry = strategy_agent.run(packet, failure_case=failure)
        risk_retry = risk_agent.run(strategy_retry)
        report_retry, failure_retry = backtest_agent.run(risk_retry)
        return report_retry

    return report
```

### 재실행 원칙
- retry는 **최대 1회**
- 재실행은 failure card가 명시적일 때만
- retry 결과도 별도 버전으로 저장

## 7. Quant / Market / News 구현 방향

## 7.1 Quant Prefilter

### 역할
DOW30 전체를 빠르게 점수화해 shortlist를 만드는 모듈

### 현재 후보군
- LightGBM ranker
- XGBoost ranker
- factor score ensemble
- AlphaGAT Stage I-inspired factor scoring

### MVP 추천 전략
- **강한 전통 baseline 1개 + 가벼운 learned variant 1개**
- 예: `LightGBM ranker`를 주 baseline으로 두고, learned factor block은 확장으로 둔다

### 출력
- 종목별 rank score
- percentile
- uncertainty flag
- top positive / negative factor contributors

---

## 7.2 Market Analyst

### 역할
수치 기반 evidence를 사람이 읽을 수 있는 구조로 정리하는 모듈

### 권장 입력
- quant score
- top factor contributors
- momentum / mean reversion flags
- volatility flag
- regime flag

### 권장 출력
- market thesis
- supporting evidence
- counter evidence
- action bias

### 중요한 점
- raw 숫자 dump를 직접 LLM에 주지 않는다.
- 먼저 `QuantEvidenceCard` 형태로 압축한 뒤 전달한다.

---

## 7.3 News Analyst Lite

### 역할
최근 뉴스 방향성과 근거를 짧게 요약하는 모듈

### MVP 입력 제약
- 종목당 최근 24시간 상위 3개 헤드라인/짧은 요약
- timestamp <= T일 16:00 ET
- relevance check 통과 기사만 사용

### 출력 필드
- direction
- evidence
- confidence
- skip_reason(optional)

### 확장 포인트
- refined news
- memory / notes
- retrieval augmentation

## 8. 실험 운영계획

## 8.1 최소 baseline 세트

| 유형 | 최소 1개는 반드시 필요 |
|---|---|
| Quant baseline | LightGBM or XGBoost ranker |
| Text baseline | sentiment-only or rules-only news baseline |
| Full runtime baseline | Quant-only (S0) |
| Risk baseline | no-risk (R0) |

## 8.2 핵심 실험표

### Signal table
| 실험 | 설명 | 기대 확인 포인트 |
|---|---|---|
| S0 | Quant only | 기본선 |
| S1 | + Market | 수치 근거 해석 추가 효과 |
| S2 | + News Lite | 뉴스 반영 이득 |
| S3 | + Synthesizer | 최종 종합의 일관성 효과 |
| S4 | + Memory/Notes | 장기 문맥 이득 |

### Risk table
| 실험 | 설명 | 기대 확인 포인트 |
|---|---|---|
| R0 | Risk 없음 | raw signal distribution |
| R1 | + position cap + stop-loss | MDD 개선 |
| R2 | + turnover/volatility control | turnover, stability 개선 |
| R3 | + full risk | 최종 리스크 구조 효과 |

## 11. 가장 큰 리스크 7개

| 리스크 | 증상 | 대응 |
|---|---|---|
| 범위 폭발 | Fundamental, graph, RL 다 넣고 싶어짐 | MVP/확장 분리 고정 |
| 데이터 누수 | close 기준 판단/집행 혼동 | T 16:00 -> T+1 open 절대 규칙 |
| 뉴스 정합성 문제 | ticker 매칭 엉킴 | 뉴스 소스 최소화, meta 중심 |
| LLM 비용 증가 | 백테스트 전체에 과도한 호출 | shortlist only, caching |
| 모델 결정 지연 | 회의만 하고 못 정함 | 후보 2개만 남기고 비교 |
| FE/BE와 계약 불일치 | API와 카드 구조 어긋남 | artifact schema를 우선 고정 |
| 실험 미완성 | 제품은 되는데 연구표 없음 | S/R ablation을 2주 일찍 시작 |
