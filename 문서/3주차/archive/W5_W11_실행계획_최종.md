## 0. W5~W11은 왜 이렇게 구성하는가

W1~W4에서 **5-agent 파이프라인의 골격**이 완성되었다.

- Data Agent: DMP + TTP + backfill ✅
- Risk Agent: v3 (2-tier + PFS + HMP + turnover/stop-loss) ✅
- Final Decision Agent: 독립 모듈 + prompt contract ✅
- Strategy Agent: mock SC 기반 동작 ✅ (real SC는 미연결)
- Backtest Agent: ❌ 미구현

W5~W11은 이 골격 위에 **3가지를 완성**하는 기간이다.

1. **real integration** — mock이 아닌 실제 StrategyCard/LLM/Backtest 연결
2. **feature 고도화** — MLF-lite + UMI-lite로 제안서 Quant backbone 완성
3. **검증 + 운영** — ablation, paper trading, 재현성 bundle

### 순서 원칙

제안서 v11과 최신 문헌이 공통으로 강조하는 원칙:

> **검증(Backtest/UQ freeze)을 실행(paper trading)보다 먼저 고정한다.**

따라서: W6 = Backtest freeze → W7 = mock trading gateway 순서로 배치한다.

## 8. 제안서 v11 업데이트 권장 (3문장)

현재 코드에 이미 PortfolioState와 HourlyMarketPatch가 구현되어 있으므로, 제안서에 아래 내용을 추가하면 문서-코드 정합성이 높아진다.

### 1) 운영 cadence 문장
> 연구/백테스트 canonical cadence는 t일 18:00 KST snapshot 기반의 일별 pipeline을 유지한다. 다만 서비스/모의 자동매매 운영에서는 DailyMarketPacket을 backbone으로 사용하고, 장중 1시간 단위의 HourlyMarketPatch를 추가 반영한다.

### 2) 운영 artifact 문장
> 모의 자동매매 운영을 위해 상태성 artifact인 PortfolioState와 장중 delta artifact인 HourlyMarketPatch를 추가 사용한다. PortfolioState는 진입가·보유일수·실제 turnover를 추적하고, HourlyMarketPatch는 daily backbone 위에 장중 가격/뉴스/시장스트레스 증분을 반영한다.

### 3) FDA Phase 문장
> Phase 1(W1~W4)의 Final Decision Agent는 deterministic pre-check와 LLM explanation wrapper 중심으로 구현하며, Phase 2부터 BacktestReport와 conflict-resolution prompt를 포함한 full constrained FDA로 확장한다.
