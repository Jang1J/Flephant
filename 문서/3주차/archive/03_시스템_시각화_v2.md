# 시스템 시각화 v2

> 목적: 팀원이 이 문서 하나만 보고도 **전체 아키텍처, 데이터 흐름, 연구 루프, 누수 정책, 실험 구조**를 동시에 이해하도록 만드는 시각화 문서.

> **주의**: 아래에 적힌 모델명은 설계 예시다. 최종 모델 선택은 별도 회의에서 확정한다.  
> **고정된 것은 구조와 계약**이고, 모델은 그 위에 얹는 구현 선택지다.

---

## 0. 전체 구조를 먼저 한 번에 보면

```text
┌───────────────────────────────────────────────────────────────────────┐
│                     OUTER RESEARCH LOOP (후속연구)                     │
│        hypothesis -> factor/model proposal -> implement -> eval      │
│                     -> analysis -> next direction                     │
│              (R&D-Agent-Quant / AlphaAgent 계열이 들어갈 곳)         │
└───────────────────────────────┬───────────────────────────────────────┘
                                │
                                ▼
┌───────────────────────────────────────────────────────────────────────┐
│                     RUNTIME TRADING SYSTEM (이번 학기 코어)            │
│                                                                       │
│  Data Agent -> Strategy Agent -> Risk Agent -> Backtest Agent         │
│       │             │                 │                    │           │
│       ▼             ▼                 ▼                    ▼           │
│  DailyPacket   StrategyCard      RiskCard/Plan     Backtest/Failure   │
│                                                                       │
│                 └──────────── feedback ────────────┘                  │
└───────────────────────────────────────────────────────────────────────┘
```

핵심은 다음이다.

- **이번 학기 코어**는 Runtime Trading System이다.
- Outer Research Loop는 설계적으로만 얹고, runtime core를 대체하지 않는다.
- 새로 읽은 6편 논문은 이 두 루프 중 어디에 들어가는지가 다르다.

## 1. 6편 논문의 위치를 그림으로 보면

```text
[System / Orchestrator Layer]
    MetaGPT

[Strategy Internal Division]
    TradExpert

[Strategy Reasoning / Fusion Layer]
    AAPM

[Quant Core / Factor Engine / Future Allocator]
    AlphaGAT + AlphaAgent

[Offline Research Outer Loop]
    R&D-Agent-Quant
```

### 한 줄 해석

```text
MetaGPT는 시스템을 묶고,
TradExpert는 Strategy를 쪼개고,
AAPM은 Strategy를 깊게 만들고,
AlphaGAT/AlphaAgent는 Quant를 강하게 만들고,
R&D-Agent-Quant는 장기적으로 연구 자동화를 맡는다.
```

## 4. Data Clock / Leakage Timeline

```text
T일 시장 마감 (16:00 ET) -----------------------------------------------
        │
        ├─ 가격 정보: T일까지 사용 가능
        ├─ 뉴스 정보: timestamp <= 16:00 ET 까지만 사용 가능
        └─ 16:00 이후 뉴스: 사용 금지 -> T+1 정보셋으로 이월

T일 밤 ---------------------------------------------------------------
        │
        ├─ Data Agent가 DailyMarketPacket 생성
        ├─ Strategy Agent가 StrategyCard 생성
        ├─ Risk Agent가 OrderPlan 생성
        └─ Backtest Agent가 같은 규칙으로 과거 구간 검증

T+1일 시초 ------------------------------------------------------------
        │
        └─ 실행 가격은 T+1 open
```

### 누수 방지 문장

- `T일 정보 -> T+1 open 집행`을 절대 깨지 않는다.
- 16:00 이후 기사 귀속을 애매하게 처리하지 않는다.
- same-day close를 매매 체결 가격으로 쓰지 않는다.

## 6. Feedback Loop 단독 시각화

```text
StrategyCard
   │
   ▼
Risk Agent
   │
   ▼
Backtest Agent
   │
   ├─ 성능 양호 -> 종료
   │
   └─ 실패 / breach 발견
          │
          ▼
   FailureCaseCard 발행
          │
          ▼
   Orchestrator가 제약 강화
          │
          ▼
   Strategy Agent 1회 재실행
```

### 이 루프의 의미

- MetaGPT의 executable feedback를 금융판으로 번역한 구조
- 단순 self-reflection이 아니라 **실행 결과로 판단 구조를 다시 수정**하는 구조
- 실패 분석이 보고서에만 남는 것이 아니라 runtime에 실제 반영됨

## 7. 실험 구조 시각화

## 7.1 Signal Stack

```text
S0  Quant only
 │
 ▼
S1  + Market Analyst
 │
 ▼
S2  + News Analyst Lite
 │
 ▼
S3  + General Synthesizer
 │
 ▼
S4  + Memory / Notes
```

## 7.2 Risk / Execution Stack

```text
R0  Risk 없음
 │
 ▼
R1  + position cap + stop-loss
 │
 ▼
R2  + turnover / volatility control
 │
 ▼
R3  + full risk agent
```

### 어떻게 읽어야 하나

- S 실험은 **신호의 질**이 좋아지는지 본다.
- R 실험은 **리스크 분포와 실행 품질**이 좋아지는지 본다.
- 둘을 혼동하지 않는다.
