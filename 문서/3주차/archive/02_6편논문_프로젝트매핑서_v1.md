# 6편 논문 프로젝트 매핑서 v1

> 목적: 지금까지 분석한 6편의 논문을 **어느 층위에서, 어떤 강도로, 어떤 시점에** 프로젝트에 반영할지 팀 차원에서 동일하게 이해하기 위한 기준 문서.

---

## 0. 먼저 결론

이 6편은 모두 중요하지만, **같은 자리에 넣는 논문이 아니다.**  
가장 안전한 이해는 아래 구조다.

```text
Layer 1. System / Orchestrator / SOP
  -> MetaGPT

Layer 2. Strategy Internal Division
  -> TradExpert

Layer 3. Strategy Reasoning / Fusion / Evaluation Discipline
  -> AAPM

Layer 4. Quant Core / Factor Engine / Portfolio Engine
  -> AlphaGAT, AlphaAgent

Layer 5. Offline Research Outer Loop
  -> R&D-Agent-Quant
```

즉, 새로 추가된 3편은 기존 3편을 대체하는 것이 아니라, **정량 코어와 연구 루프를 보강하는 역할**로 읽는 것이 가장 정확하다.

---

## 1. 6편 논문을 한 장으로 구분하면

| 논문 | 실제로 답하는 질문 | 우리 프로젝트에서의 위치 | 이번 학기 반영 강도 |
|---|---|---|---|
| **MetaGPT** | 여러 agent가 복잡한 일을 어떻게 덜 망가지게 협업하는가? | System / Orchestrator / Artifact Layer | **MVP 필수** |
| **TradExpert** | 뉴스/시장/알파/펀더멘털을 전문가 분업으로 어떻게 종합하는가? | Strategy 내부 분업 | **MVP 필수(축소형)** |
| **AAPM** | 뉴스 정성신호를 정량 팩터와 어떻게 결합하는가? | Strategy 확장 reasoning/fusion + 평가 규율 | **MVP-lite + 1차 확장** |
| **AlphaGAT** | raw market data에서 적응형 포트폴리오를 어떻게 만들까? | Quant Prefilter / Factor Engine / future allocator | **즉시 반영 가능** |
| **AlphaAgent** | 빨리 죽지 않는(alpha decay-resistant) 알파를 어떻게 발명할까? | Factor/Alpha Analyst 확장 | **1차 확장** |
| **R&D-Agent-Quant** | factor와 model을 함께 발명·구현·검증하는 연구공장을 만들 수 있는가? | Offline quant research outer loop | **후속연구 / 부록** |

## 2. MetaGPT

## 2.1 이 논문을 한 문장으로 요약하면

> **MetaGPT는 agent를 더 많이 두는 논문이 아니라, 여러 agent가 SOP와 structured artifact 아래에서 안정적으로 협업하도록 통제하는 논문이다.**

## 2.2 우리 프로젝트에서의 정확한 역할

MetaGPT는 개별 agent 내부 모델을 알려주는 논문이 아니다.  
우리 프로젝트에서는 아래 요소만 가져오면 된다.

### 가져올 것
- SOP 기반 역할 분화
- structured artifact
- shared message pool / artifact registry
- dependency-based activation
- executable feedback

### 가져오지 않을 것
- 소프트웨어 회사 역할 체계를 그대로 복제하는 것
- MetaGPT 전체 프레임워크 재현
- 코드 생성 benchmark 성능 숫자

## 2.3 왜 상단 레이어에 두는가

MetaGPT는 “무슨 모델을 쓸까”보다,

- 누가 언제 실행되는지
- 무엇을 다음 단계로 넘기는지
- 실패를 어떻게 다시 반영하는지

를 정의한다.  
따라서 MetaGPT는 Data/Strategy/Risk/Backtest **각 agent 내부**보다 **Orchestrator / Message Protocol / Artifact Registry 층**에 두는 것이 맞다.

## 2.4 우리 시스템으로 번역하면

| MetaGPT 개념 | 우리 프로젝트 번역 |
|---|---|
| PRD / 설계문서 / 태스크 | `DailyMarketPacket`, `StrategyCard`, `RiskCard`, `BacktestReport`, `FailureCaseCard` |
| Shared message pool | SQLite artifact registry |
| Subscription | prerequisite 충족 시에만 실행 |
| Executable feedback | FailureCaseCard를 반영한 1회 재실행 |

## 3. TradExpert

## 3.1 이 논문을 한 문장으로 요약하면

> **TradExpert는 뉴스·시장·알파·펀더멘털을 각각 다른 전문가가 보고서를 만들고, 마지막에 General Expert가 prediction 또는 ranking 결정을 내리는 trading-oriented MoE 논문이다.**

## 3.2 우리 프로젝트에서의 정확한 역할

TradExpert는 현재 프로젝트에서 **Strategy Agent 내부 구조의 1순위 레퍼런스**다.

### 꼭 가져올 것
- data-source별 전문가 분업
- Market / News 우선순위
- General Synthesizer 구조
- 전 종목이 아닌 shortlist에만 LLM 적용하는 원칙

### 가져오되 축소할 것
- Alpha Expert
- Fundamental Analyst
- comparator 기반 ranking 사고방식

### 가져오지 않을 것
- 4개 LLM 모두 LoRA fine-tuning
- O(N²) ranking full reproduction
- full data preprocessing 재현
- time-series reprogramming full stack

## 3.3 가장 중요한 ablation 교훈

TradExpert 원문의 핵심은 전문가 우선순위다.

```text
Market 제거 -> 큰 성능 하락
News 제거   -> 큰 성능 하락
Alpha 제거  -> 중간 수준 하락
Fundamental 제거 -> 상대적으로 작은 하락
```

따라서 우리 프로젝트의 우선순위는 아래처럼 간다.

1. **Quant Prefilter**
2. **Market Analyst**
3. **News Analyst Lite**
4. **General Synthesizer**
5. Factor / Alpha Analyst
6. Fundamental Analyst

## 3.4 현재 구조에 번역한 최종형

```text
DOW30 전체
  -> Quant Prefilter
  -> Top 5~8 shortlist
  -> Market Analyst
  -> News Analyst Lite
  -> General Synthesizer
  -> StrategyCard
```

핵심은 TradExpert를 “4개 LLM 시스템”으로 따라 하는 것이 아니라, **전략 판단을 단계별로 분업하는 구조**로 번역하는 것이다.

## 4. AAPM

## 4.1 이 논문을 한 문장으로 요약하면

> **AAPM은 LLM이 만든 정성 분석 보고서를 manual factor와 결합해 hybrid asset pricing state로 사용하는 논문이다.**

## 4.2 우리 프로젝트에서의 정확한 역할

AAPM은 Data Agent 논문처럼 보일 수 있지만, 실제 핵심은 **Strategy 확장 reasoning/fusion**이다.

### Data Agent에 가볍게 들어가는 것
- refined news
- relevance check

### Strategy 확장에 강하게 들어가는 것
- iterative refinement
- memory / notes
- retrieval
- report embedding + factor fusion
- leakage-aware evaluation mindset

## 4.3 왜 Strategy 확장에 두는가

AAPM의 진짜 기여는 “뉴스를 잘 읽는다”가 아니라,

- 뉴스로부터 보고서를 만들고
- 그 보고서를 daily state로 만들고
- manual factor와 결합해
- prediction network로 연결하는

**정성-정량 fusion architecture**에 있기 때문이다.

## 4.4 현재 프로젝트로 번역하면

### MVP-lite
- 뉴스 relevance check
- refined news
- 정성/정량 분리 후 결합 원칙

### 1차 확장
- memory / notes
- retrieval
- report-like summary state
- General Synthesizer 강화

### 평가 규율로서 가져와야 할 것
- knowledge cutoff 이후 평가 우선
- 어려운 경우 leakage limitation 명시
- 결과를 strict finance claim이 아니라 architecture/evaluation claim으로 해석

---

## 5. AlphaGAT

## 5.1 이 논문을 한 문장으로 요약하면

> **AlphaGAT은 raw market data를 robust한 alpha factors로 바꾸는 Stage I과, 그 factor들을 PPO+GAT로 동적으로 조절하는 Stage II를 분리한 2-stage adaptive portfolio selection 논문이다.**

## 5.2 우리 프로젝트에서의 정확한 역할

AlphaGAT은 현재 프로젝트의 **정량 코어 설계**에 가장 직접적으로 연결된다.

### Stage I이 주는 것
- raw data -> factor / alpha space 변환
- multi-period / cross-asset relation 반영
- factor diversity를 고려한 설계
- Quant Prefilter와 Factor Engine 설계 아이디어

### Stage II가 주는 것
- factor weight 동적 조절
- 향후 portfolio allocator / advanced risk policy 설계
- RL을 “최종 buy/sell/hold 예측기”가 아니라 **factor/weight 조절기**로 쓰는 관점

## 5.3 현재 프로젝트에 어떻게 꽂히나

### MVP / 가까운 구현
- Stage I 철학을 Quant Prefilter에 반영
- manual factor + learned factor 조합을 고려
- 5/20/60 multi-period features 강화

### 1차~2차 확장
- allocator / dynamic weighting
- RL을 shortlist 이후 포트폴리오 weight 조절기로 제한적 사용

### 안 하는 것
- AlphaGAT full reproduction
- Stage II PPO+GAT를 MVP에 곧바로 탑재

---

## 6. AlphaAgent

## 6.1 이 논문을 한 문장으로 요약하면

> **AlphaAgent는 LLM의 factor 탐색을 originality, hypothesis alignment, complexity control로 정규화해 alpha decay에 더 강한 팩터를 찾으려는 논문이다.**

## 6.2 우리 프로젝트에서의 정확한 역할

AlphaAgent는 현재 프로젝트에서 **Factor / Alpha Analyst 설계 원리**를 제공한다.

### 가져올 것
- alpha decay를 고려한 factor mining 관점
- novelty / originality 중요성
- 너무 복잡한 식을 억제하는 규율
- idea -> factor -> evaluation loop라는 폐루프 사고방식

### 가져오지 않을 것
- full AST novelty engine
- factor invention loop full reproduction
- 이번 학기 MVP에서의 full multi-agent alpha lab 구현

## 6.3 어디에 들어가나

- MVP core에는 직접 안 들어감
- 1차 확장의 **Factor / Alpha Analyst**에 들어감
- “factor를 늘리는 것”보다 “덜 겹치고 덜 빨리 죽는 factor”가 중요하다는 규율로 사용

---

## 7. R&D-Agent-Quant

## 7.1 이 논문을 한 문장으로 요약하면

> **R&D-Agent-Quant는 factor와 model을 함께 발명·코딩·백테스트·선택하는 오프라인 quant 연구공장 논문이다.**

## 7.2 우리 프로젝트에서의 정확한 역할

이 논문은 현재 4-agent trading runtime의 코어가 아니다.  
더 정확히는 **runtime system 바깥에서 돌아가는 outer research loop**다.

### 가져올 것
- research -> development -> feedback의 루프
- factor-model co-optimization 관점
- 구현/검증/분석 단계 분리
- 다음 탐색 방향을 선택하는 scheduler 관점

### 가져오지 않을 것
- 이번 학기 안에 full auto-quant lab 구축
- runtime trading loop를 이 논문 구조로 대체

## 7.3 어디에 들어가나

- 부록 / 후속연구
- strategy 개선을 위한 offline experiment pipeline
- 장기적으로는 팀의 “연구 자동화 엔진” 역할

## 8. 6편 논문을 4-agent 아키텍처에 꽂아보면

## 8.1 Agent별 매핑

| 에이전트/레이어 | 핵심 논문 | 보조 논문 | 설명 |
|---|---|---|---|
| Orchestrator / Artifact Registry | **MetaGPT** | R&D-Agent-Quant | SOP, dependency, shared registry, feedback loop |
| Data Agent | AAPM(약하게) | TradExpert(관점) | refined news, relevance check, source separation |
| Strategy Agent (MVP) | **TradExpert** | MetaGPT, AAPM | Quant Prefilter -> Market -> News -> Synthesizer |
| Strategy Agent (1차 확장) | **AAPM**, AlphaAgent | AlphaGAT | memory/notes/retrieval, Factor/Alpha Analyst |
| Risk Agent | AlphaGAT(Stage II 철학) | AAPM(평가 태도) | allocator / dynamic weighting / advanced gating |
| Backtest Agent | MetaGPT | R&D-Agent-Quant | executable feedback, failure-case-driven correction |
| Offline Research Loop | **R&D-Agent-Quant** | AlphaAgent | factor-model co-design |

## 8.2 최종 해석 문장

```text
상위 협업 구조는 MetaGPT식으로 만들고,
전략 내부 분업은 TradExpert식으로 설계하며,
정성-정량 fusion과 memory 확장은 AAPM식으로 가져가고,
정량 코어 확장은 AlphaGAT과 AlphaAgent로 보강하며,
장기적으로는 R&D-Agent-Quant식 outer research loop를 붙인다.
```

## 10. 팀원이 자주 하는 오해 10개

1. **MetaGPT는 전략 모델 논문이다.**  
   → 아니다. 협업 구조 논문이다.

2. **AAPM은 Data Agent 논문이다.**  
   → 일부만 그렇고, 실제 핵심은 Strategy 확장 fusion 논리다.

3. **TradExpert를 그대로 구현하면 프로젝트가 끝난다.**  
   → 아니다. full LoRA와 full ranking 재현은 범위 밖이다.

4. **새로 추가된 3편이 기존 3편을 대체한다.**  
   → 아니다. 정량 코어를 보강한다.

5. **AlphaGAT을 넣으려면 RL을 MVP부터 꼭 써야 한다.**  
   → 아니다. Stage I 철학만 먼저 반영할 수 있다.

6. **AlphaAgent는 지금 당장 팩터 발명기를 만들어야 한다는 뜻이다.**  
   → 아니다. Factor/Alpha Analyst 설계 원리로 읽는 게 맞다.

7. **R&D-Agent-Quant는 곧 Runtime Trading Agent다.**  
   → 아니다. outer research loop다.

8. **모든 agent가 LLM이어야 한다.**  
   → 아니다. Data/Risk/Backtest는 software agent가 더 자연스럽다.

9. **전 종목 LLM 분석을 해야 agent 프로젝트처럼 보인다.**  
   → 아니다. 오히려 범위를 망친다.

10. **최고 성능이 이 프로젝트의 유일한 목표다.**  
    → 아니다. 구조화된 협업과 설명 가능한 의사결정이 핵심 기여다.

## 11. 다음 회의에서 써먹는 빠른 결론

### 바로 확정해도 되는 것
- MetaGPT는 상단 orchestration 레이어
- TradExpert는 Strategy 내부 분업 레이어
- AAPM은 Strategy 확장 fusion 레이어
- AlphaGAT은 Quant Prefilter / future allocator 레이어
- AlphaAgent는 Factor/Alpha Analyst 확장 레이어
- R&D-Agent-Quant는 outer research loop 레이어

### 아직 열어둬야 하는 것
- Quant Prefilter의 구체 모델
- Market Analyst의 구현 형태
- News Analyst Lite의 입력 범위
- Factor/Alpha Analyst의 1차 구현 방식
- allocator를 RL로 할지 rules+optimizer로 할지

### 최종 문장
> **6편 논문은 서로 경쟁하는 설계안이 아니라, 서로 다른 층위를 채우는 부품들이다.**
