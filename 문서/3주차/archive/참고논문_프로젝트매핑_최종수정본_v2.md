# 참고논문 3편 프로젝트 매핑 최종 수정본 v2

> 팀 내부 공유용 문서  
> 목적: 교수님 지정 참고논문 3편(MetaGPT, AAPM, TradExpert)을 우리 종합설계1 프로젝트에 **어느 층위에, 어떤 강도로, 어떤 순서로 적용할지** 팀 차원에서 동일하게 이해하기 위한 기준 문서.

---

## 0. 이 문서에서 먼저 확정하는 핵심

이 3편은 모두 “에이전트”를 말하지만, **같은 종류의 논문이 아니다.**  
그래서 프로젝트에 넣는 위치도 달라야 한다.

| 논문 | 실제로 답하는 질문 | 우리 프로젝트에서 들어가는 위치 |
|---|---|---|
| **MetaGPT** | 여러 agent가 복잡한 작업을 어떻게 안정적으로 협업하는가? | **상위 시스템 구조 / 오케스트레이터 / 메시지 프로토콜** |
| **AAPM** | 뉴스에서 얻은 정성 신호를 정량 팩터와 어떻게 결합하는가? | **Strategy Agent의 확장 reasoning/fusion 층 + 평가 규율** |
| **TradExpert** | 뉴스/시장/알파/펀더멘털을 전문가 분업으로 어떻게 종합해 트레이딩 결정을 내리는가? | **Strategy Agent 내부 전문가 분업 구조** |

### 한 줄 결론

우리 프로젝트는 아래처럼 읽는 것이 가장 정확하다.

- **MetaGPT = 시스템 협업 문법**
- **TradExpert = 전략 계층의 전문가 분업**
- **AAPM = 정성-정량 결합과 memory 확장 경로**

즉, 세 논문을 똑같이 “전략 모델”로 읽으면 안 된다.

## 1. 우리 프로젝트의 기준 전제

이 문서는 아래 프로젝트 전제를 이미 확정된 것으로 둔다.

| 항목 | 기준 |
|---|---|
| 프로젝트 목표 | 에이전트를 활용한 **금융 트레이딩 시스템** 개발 |
| 시장 | 미국 주식 |
| 빈도 | 일봉 |
| 유니버스 | **2020-01-01 기준 고정 DOW30** |
| 정보 스냅샷 | **T일 16:00 ET** |
| 실행 시점 | **T+1 open** |
| 거래비용 | 편도 10bp slippage + 수수료 |
| 검증 방식 | walk-forward 최소 3-fold |
| 상위 구조 | Data / Strategy / Risk / Backtest + Orchestrator |
| 중간 산출물 | JSON 카드 + artifact registry |
| feedback | Backtest 결과를 전략 수정으로 되돌리는 loop |

### 현재 MVP 구조

```text
Data Agent
  -> DailyMarketPacket
Strategy Agent
  -> Quant Prefilter
  -> Market Analyst
  -> News Analyst Lite
  -> General Synthesizer
  -> StrategyCard
Risk Agent
  -> RiskCard + OrderPlan
Backtest Agent
  -> BacktestReport + FailureCaseCard
Orchestrator
  -> dependency 체크 + 1회 재실행 feedback
```

## 2. MetaGPT: 우리 프로젝트에 어떻게 들어가는가

## 2.1 MetaGPT에서 가져와야 할 것

MetaGPT에서 가져와야 하는 핵심은 **모델 성능 숫자**가 아니다.  
핵심은 다음 다섯 가지다.

1. **SOP 기반 역할 분화**  
   각 agent는 자유롭게 행동하는 것이 아니라, 정해진 역할·입력·출력·책임을 가진다.

2. **Structured Artifact**  
   agent 간 소통은 자유 대화가 아니라 문서/카드/스키마를 통해 이루어진다.

3. **Shared Message Pool / Artifact Registry**  
   결과물을 중앙 저장소에 쌓고, 다음 agent는 그것을 읽는다.

4. **Dependency-based Activation**  
   필요한 prerequisite가 오기 전에는 다음 단계가 실행되지 않는다.

5. **Executable Feedback**  
   실행 결과가 다시 상위 판단을 교정한다.

## 2.2 MetaGPT를 우리 프로젝트로 번역하면

소프트웨어 개발 회사의 PRD, 설계문서, 테스트 문서를 금융 도메인 카드로 치환하면 된다.

| MetaGPT 원문 역할 | 금융 프로젝트 번역 |
|---|---|
| PRD / 설계문서 / 태스크 | `DailyMarketPacket`, `StrategyCard`, `RiskCard`, `BacktestReport`, `FailureCaseCard` |
| Shared message pool | **artifact registry (SQLite/JSON 기반)** |
| 구독/활성화 | `StrategyCard` 없으면 Risk 실행 금지, `OrderPlan` 없으면 Backtest 실행 금지 |
| Executable feedback | 실패 카드 발행 -> 제약 강화 -> Strategy 1회 재실행 |

## 2.3 MetaGPT에서 **가져오지 않는 것**

아래는 참고는 하되 그대로 복제 대상은 아니다.

- 소프트웨어 회사를 그대로 재현하는 역할 체계
- 코드 생성 benchmark 성능 숫자
- 프레임워크 전체 구현체를 통째로 재현하는 것

즉, 우리 프로젝트는 **MetaGPT clone**이 아니다.  
우리는 MetaGPT의 **협업 문법**만 금융 도메인에 맞게 가져온다.

## 2.4 MetaGPT의 위치: 개별 agent 내부가 아니라 상단 시스템 레이어

이 점이 매우 중요하다.

MetaGPT는 개별 agent가 무슨 모델을 쓰는지보다,

- 어떻게 소통하고
- 어떤 형식으로 핸드오프하고
- 언제 실행되고
- 어떻게 실패를 되돌리는가

를 정의한다.

따라서 MetaGPT는 우리 시스템에서 **Data/Strategy/Risk/Backtest 각 agent 내부**보다,
**Orchestrator / Artifact Registry / Message Protocol 층**에 들어간다고 보는 것이 맞다.

## 3. TradExpert: 우리 프로젝트에 어떻게 들어가는가

## 3.1 TradExpert에서 가져와야 할 것

TradExpert의 핵심은 **전략 계층의 전문가 분업**이다.

전략 판단을 하나의 모델이 통째로 하는 대신,

- News Analyst
- Market Analyst
- Alpha Expert
- Fundamental Analyst
- General Expert

로 나눈 뒤, 마지막에 General Expert가 종합한다.

이 구조는 현재 우리 Strategy Agent의 내부 구조와 가장 직접적으로 맞닿아 있다.

## 3.2 TradExpert에서 우리에게 중요한 핵심 교훈

### 교훈 1. Market과 News가 가장 중요하다

원문 ablation의 핵심 메시지는 단순하다.

- **Market Analyst 제거** -> 성능 큰 폭 하락
- **News Analyst 제거** -> 성능 큰 폭 하락
- Alpha 제거 -> 영향은 있지만 중간
- Fundamental 제거 -> 상대적으로 가장 작은 영향

따라서 스코프를 줄여야 할 때 우선순위는 아래처럼 가야 한다.

1. **Market Analyst 유지**
2. **News Analyst 유지**
3. Alpha는 1차 확장
4. Fundamental은 후순위

### 교훈 2. 전 종목에 LLM을 돌리면 안 된다

TradExpert는 comparator 기반 ranking에서 O(N²) 비교를 사용하고, 단일 종목 처리 시간도 무겁다.  
우리 프로젝트가 DOW30 기준으로도 반드시 **shortlist 구조**를 가져가야 하는 이유다.

즉, Strategy Agent의 진짜 시작점은 아래다.

```text
DOW30 전체
  -> Quant Prefilter
  -> Top 5~8 shortlist
  -> 그 다음에만 Market/News/General LLM 분석
```

### 교훈 3. 순수 LLM 시스템이 아니라 하이브리드 구조다

TradExpert 원문에서도 Alpha Expert는 **LightGBM 기반 스코어링 모델**로 상위 factor를 고른 뒤 LLM에 전달한다.  
즉, TradExpert 자체도 “모든 걸 LLM이 직접 한다”가 아니라 **ML + LLM 하이브리드**다.

## 3.3 TradExpert를 우리 프로젝트로 번역하면

### MVP에서 가져올 것

- **Quant Prefilter**
- **Market Analyst**
- **News Analyst Lite**
- **General Synthesizer**

### 1차 확장

- **Factor/Alpha Analyst**

### 2차 확장

- **Fundamental Analyst**

## 3.4 TradExpert에서 **가져오지 않는 것**

아래는 그대로 구현하지 않는다.

- 4개 Expert LLM 전부 LoRA fine-tuning
- OHLCV reprogramming 전체 재현
- pairwise comparator O(N²) ranking의 full-scale 구현
- 원문과 동일한 데이터셋 전처리 전체

우리는 TradExpert의 **전문가 우선순위와 분업 구조**를 가져오는 것이지,
논문 전체를 축소 복제하는 것이 아니다.

## 4. AAPM: 우리 프로젝트에 어떻게 들어가는가

## 4.1 AAPM에서 가져와야 할 것

AAPM의 핵심은 “뉴스를 읽는 agent” 그 자체보다,
**정성 보고서와 정량 팩터를 어떻게 결합할 것인가**에 있다.

가져와야 할 핵심은 아래 다섯 가지다.

1. **Refined News**: raw news를 짧고 표준화된 형태로 정리
2. **Relevance Check**: 투자적으로 무관한 뉴스는 skip
3. **Memory / RAG**: 관련 지식을 검색해 해석 보강
4. **Macro/Micro Notes**: 장기 문맥, 시장 관찰, 투자 아이디어 유지
5. **Report Embedding + Manual Factor Fusion**: 정성과 정량을 따로 처리한 뒤 결합

## 4.2 AAPM의 위치: Data Agent보다 Strategy 확장에 더 가깝다

이 부분이 중요하다.

AAPM을 Data Agent에만 넣으면 해석이 약해진다.  
물론 아래 요소는 Data Agent에 일부 들어갈 수 있다.

- refined news
- relevance check

하지만 AAPM의 진짜 강점은 아래에 있다.

- iterative refinement
- memory / notes
- report embedding
- factor fusion
- leakage-aware evaluation mindset

즉, AAPM은 **Data Agent용 논문**이 아니라,
**Strategy Agent의 1차 확장 reasoning/fusion 층**으로 읽는 것이 더 정확하다.

## 4.3 AAPM을 우리 프로젝트로 번역하면

### MVP-lite에서 가져올 것

- 뉴스 relevance check
- refined news
- 정성(텍스트)과 정량(수치)을 따로 처리한 뒤 결합한다는 설계 원칙

### 1차 확장에서 가져올 것

- memory / notes
- retrieval
- report embedding + factor fusion
- General Synthesizer 강화

### 2차 이후 고려할 것

- 더 깊은 iterative refinement
- 더 넓은 knowledge base
- asset-specific embedding에 대응하는 고급 구조

## 4.4 AAPM에서 반드시 가져와야 하는 태도: leakage awareness

AAPM은 knowledge cutoff 이후부터 데이터셋을 시작해 LLM 사전학습 지식 누수를 줄이려 했다.

우리 프로젝트도 그 정신은 반드시 가져와야 한다.

다만 현실적으로는 다음처럼 정리하는 것이 좋다.

- 가능한 경우 **knowledge-cutoff 이후 구간 평가를 우선**한다.
- 적용이 어려운 구간은 **LLM pretraining leakage limitation**으로 명시한다.
- 결과는 strict asset-pricing claim보다 **architecture ablation + engineering evaluation** 중심으로 해석한다.

즉, AAPM의 knowledge cutoff 방식은 “무조건 그대로”가 아니라,
**평가 규율의 기준점**으로 가져오는 것이다.

## 5. 세 논문의 최종 매핑: 한 장 요약

## 5.1 층위별 매핑

| 프로젝트 층위 | 주로 대응하는 논문 | 핵심 적용 내용 |
|---|---|---|
| **System / Orchestrator Layer** | **MetaGPT** | SOP, 카드 스키마, artifact registry, dependency, feedback loop |
| **Strategy Agent Internal Structure** | **TradExpert** | Quant Prefilter -> Market -> News -> Synthesizer, 전문가 우선순위 |
| **Strategy Extension / Fusion Layer** | **AAPM** | refined news, relevance check, memory/notes, report+factor fusion |
| **Evaluation Discipline** | **AAPM + TradExpert** | leakage awareness, component ablation, expert priority 검증 |

## 5.2 우리 프로젝트의 최종 해석

이 프로젝트는 다음처럼 읽는 것이 가장 정확하다.

```text
상위 협업 구조는 MetaGPT식으로 만들고,
전략 계층의 분업은 TradExpert식으로 설계하며,
정성-정량 결합과 memory 확장 경로는 AAPM식으로 가져간다.
```

## 6. 4개 에이전트에의 최종 적용 (수정본)

## 6.1 Data Agent

### 역할
가격/거래량/기술팩터/뉴스를 수집·정제해 `DailyMarketPacket`을 생성한다.

### MVP 범위
- OHLCV
- 기술팩터
- 뉴스 메타데이터
- 뉴스 기본 정제

### 논문 적용

| 논문 | 적용 내용 |
|---|---|
| **MetaGPT** | `DailyMarketPacket` JSON 스키마 고정 |
| **AAPM** | relevance check, refined news의 가벼운 버전 |
| **TradExpert** | News / Market / Alpha / Fundamental 데이터 소스 구분이라는 관점만 참고 |

### 주의
- **재무제표/실적/Fundamental은 MVP 필수 아님**
- Data Agent를 너무 크게 잡지 않는다
- Fundamental 데이터는 2차 확장으로 후퇴

---

## 6.2 Strategy Agent

### 역할
DataPacket을 받아 후보 종목을 줄이고, 분석 보고서를 종합해 최종 투자 판단인 `StrategyCard`를 만든다.

### 최종 구조

```text
Quant Prefilter
  -> Market Analyst
  -> News Analyst Lite
  -> General Synthesizer
  -> StrategyCard
```

### MVP 필수
- **Quant Prefilter**
- **Market Analyst**
- **News Analyst Lite**
- **General Synthesizer**

### 1차 확장
- Factor / Alpha Analyst
- AAPM식 memory / notes / retrieval

### 2차 확장
- Fundamental Analyst

### 논문 적용

| 논문 | 적용 내용 |
|---|---|
| **TradExpert** | 전문가 분업 구조, Market/News 우선, General Synthesizer |
| **AAPM** | 정량+정성 분리 후 결합, report/factor fusion, memory/notes 확장 |
| **MetaGPT** | `StrategyCard` 스키마 표준화 |

### 주의
- Strategy Agent 설명에서 **Quant Prefilter를 가장 먼저 명시**해야 한다.
- Strategy Agent를 “여러 모델의 앙상블”로만 이해하면 부족하다.
- 핵심은 **단계적 판단 구조 + 구조화된 산출물**이다.

---

## 6.3 Risk Agent

### 역할
`StrategyCard`를 받아 위험을 검토하고, 수정된 주문 계획을 만든다.

### MVP 범위
- position cap
- stop-loss
- turnover cap

### 논문 적용

| 논문 | 적용 내용 |
|---|---|
| **MetaGPT** | dependency 기반 실행, `RiskCard` / `OrderPlan` 스키마 고정 |
| **AAPM** | 직접 적용은 적지만 평가 태도와 leakage awareness는 공유 |
| **TradExpert** | 직접 적용은 약함 |

### 주의
- Risk는 전략의 부속 기능이 아니라 **독립 에이전트**다.
- 나중에 ablation에서 신호와 리스크 기여를 분리할 수 있어야 한다.

---

## 6.4 Backtest Agent

### 역할
`OrderPlan`을 과거 데이터에 적용해 성능을 계산하고, 실패 원인을 구조화해 다시 전략으로 되돌린다.

### MVP 범위
- next-open execution
- fee / slippage
- walk-forward evaluation
- `BacktestReport`
- `FailureCaseCard`

### 논문 적용

| 논문 | 적용 내용 |
|---|---|
| **MetaGPT** | executable feedback의 금융판 번역 |
| **AAPM** | leakage-aware evaluation, knowledge cutoff 의식 |
| **TradExpert** | AR / AV / SR / MDD 등 평가 항목, expert/stack ablation의 영감 |

### 주의
- “knowledge cutoff 이후 구간만 평가”는 이상적 원칙이다.
- 현실적으로 불가능한 경우에는 limitation으로 명시한다.
- Backtest Agent는 단순 수익률 계산기가 아니라 **실패 카드 발행자**다.

## 7. 프로젝트 설계 원칙 (최종 확정판)

### 원칙 1. MetaGPT
에이전트 간 소통은 **자유 대화가 아니라 구조화된 카드(JSON)** 로만 한다.

### 원칙 2. AAPM
정성(텍스트)과 정량(수치)은 한 번에 섞지 말고, **따로 처리한 뒤 결합**한다.

### 원칙 3. TradExpert
전략 판단은 전문가 분업으로 나누되, **Market과 News를 최우선**으로 둔다.

### 원칙 4. MetaGPT
실행 결과로 전략을 교정하는 **feedback loop**를 반드시 넣는다.

### 원칙 5. AAPM
LLM 사전학습 지식에 의한 잠재적 정보누수를 의식하고, 평가 문서에 limitation을 명시한다.

### 원칙 6. TradExpert
전 종목 LLM 분석은 금지한다. **정량 모델이 먼저 후보를 줄이고, LLM은 shortlist에만 적용**한다.

## 8. MVP / 확장 범위 최종판

| 단계 | 포함 | 미룸 |
|---|---|---|
| **MVP** | 4 agent, Quant Prefilter, Market Analyst, News Analyst Lite, Risk rule, Backtest, JSON 카드, feedback loop | Fundamental, full memory, full Alpha expert |
| **1차 확장** | AAPM식 memory/notes/retrieval, Factor/Alpha Analyst, Synthesizer 강화 | Fundamental full version |
| **2차 확장** | Fundamental Analyst, relation graph, 더 정교한 risk gating | full LoRA, full TradExpert ranking, heavy multi-LLM stack |

---

## 9. 오해 방지 문장 (팀원이 반드시 알아야 할 것)

1. **MetaGPT는 금융 논문이 아니라 협업 구조 논문이다.**  
   따라서 성능 숫자보다 SOP, structured artifact, message protocol을 가져오는 것이 핵심이다.

2. **AAPM은 멀티에이전트 트레이딩 논문이 아니다.**  
   실질적으로는 하나의 분석 agent + hybrid asset pricing network에 가깝다.

3. **TradExpert를 그대로 구현하는 것이 목표가 아니다.**  
   LoRA fine-tuning과 O(N²) ranking까지 모두 재현하는 것은 범위 밖이다.

4. **모든 에이전트가 LLM일 필요는 없다.**  
   Data / Risk / Backtest는 비-LLM software agent로도 충분하다.

5. **이 프로젝트의 핵심은 최고 성능보다 구조화된 협업과 설명 가능한 의사결정이다.**

## 10. 최종 결론

현재 프로젝트의 참고논문 매핑은 아래처럼 이해하면 가장 정확하다.

```text
MetaGPT는 시스템 상단의 협업 구조를 담당한다.
TradExpert는 Strategy Agent 내부의 전문가 분업을 담당한다.
AAPM은 Strategy Agent의 확장 reasoning/fusion과 평가 규율을 담당한다.
```

그리고 이 구조를 현재 프로젝트에 맞게 번역하면 다음이 최종 해석이다.

```text
우리는 MetaGPT식 오케스트레이션 위에서,
TradExpert식 Strategy 분업 구조를 만들고,
AAPM식 정성-정량 결합과 memory 확장 경로를 얹는 방향으로 간다.
```

이 문장을 팀 전체가 동일하게 이해하면, 이후 모델 선택이나 API 설계, 카드 스키마 논의가 훨씬 빨라진다.
