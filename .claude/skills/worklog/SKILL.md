# Worklog -- 작업 로그 기록 스킬

세션별 작업 내역을 체계적으로 기록하여 프로젝트 진행 상황을 추적한다.

## 워크플로우

### 모드 1: 기록 (기본)
1. git diff/log에서 최근 변경 사항 수집
2. 작업 내역을 구조화 (카테고리별 분류)
3. 문서/worklog/ 디렉토리에 날짜별 파일로 기록

### 모드 2: 현황 보고 (status)
1. 최근 worklog 파일들 읽기
2. Phase별/Week별 진행률 집계
3. 미완료 항목 + 다음 단계 요약

## 로그 포맷

```markdown
# Worklog YYYY-MM-DD

## 세션 요약
- 주요 작업: [1줄 요약]
- 소요 시간: [추정]

## 변경 사항

### 추가
- [파일명]: [설명]

### 수정
- [파일명]: [변경 내용]

### 삭제
- [파일명]: [사유]

## 검증 결과
- [ ] 스키마 검증 PASS/FAIL
- [ ] 파이프라인 실행 PASS/FAIL

## 다음 단계
- [ ] 작업 1
- [ ] 작업 2

## 관련 커밋
- [commit hash]: [메시지]
```

## 저장 위치

- 경로: `문서/worklog/YYYY-MM-DD.md`
- 같은 날 여러 세션이면 기존 파일에 append (## 세션 2, 세션 3...)
- `문서/worklog/` 디렉토리가 없으면 생성

## 진행률 추적

Week별 진행률을 AI_파트_분배_v1.md의 W1~W11 로드맵과 대조하여 추적:

```markdown
| Week | 계획 | 실제 | 진행률 |
|------|------|------|--------|
| W1-W4 | Phase 1 기본 파이프라인 | ... | XX% |
| W5-W8 | Phase 2 실전략 통합 | ... | XX% |
| W9-W11 | Phase 3 운영/검증/발표 | ... | XX% |
```
